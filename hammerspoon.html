Window mode — Meh+W toggles (Hammerspoon, ~/.hammerspoon/windows-position.lua)

A modal: press Meh+W once to enter, everything below then works with no modifier until you press Esc (or Meh+W again) to exit. g, Shift+g, and the arrow keys exit on their own as soon as they fire — they're one-shot, one press is the whole job, no cycle to land wrong on. e s d f (resize/snap) and c (center %) leave the mode running, since pressing again is how you cycle to the next size. An on-screen alert stays up the whole time as a reminder you're in it.

On the Totem, Meh is the home-row hold on , (or C) — ctrl+alt+shift, no cmd. Not Ctrl+Alt+W: that's Wispr Flow's dictation trigger (totem.keymap:373). Not Hyper (V/M hold): Hyper+H is already the neru grid, and macOS's own Caps-Lock Hyper is a separate, fully-claimed namespace of app launchers (Karabiner). Meh was free — totem.keymap earmarks it for exactly this ("no app claims these, so they are safe for global hotkeys"). Nothing below is bound outside the mode — that's the point: it used to be bare Ctrl+E/S/D/F/G and Ctrl+Alt+D/E/G all the time, which shadowed normal app shortcuts (Ctrl+S=save, Ctrl+Alt+D=duplicate tab, etc).

ssnap left, repeat to cycle width 1/2 → 1/3 → 2/3
fsnap right, same cycle
esnap top, repeat to cycle height 1/2 → 1/3 → 2/3
dsnap bottom, same cycle
s + f heldfull width
e + d heldfull height
ccenter, repeat to cycle size 100% → 133% → 200%
g (one-shot)full size: fill the whole screen, still an ordinary window (deterministic — unlike c, always lands here regardless of where its cycle was)
Shift+g (one-shot)actual macOS full screen: separate Space, no menu bar/Dock
↑ (one-shot)re-apply the focused app's configured layout (no-op if it has none)
↓ (one-shot)re-apply every app's configured layout
← (one-shot)send focused window to the previous screen, keeping relative size/position
→ (one-shot)send focused window to the next screen, same

e s d f are in the same physical positions as the nav layer's arrows (e=up, s=left, d=down, f=right), not literal hjkl or arrow keys — the actual arrow keys are a separate, one-shot group for layout/screen-move.

Configured app layouts (for ↑ / ↓)

The layouts table in windows-position.lua is a list of {app names, layout function} entries — the function could position by grid cell, pin to a screen, etc. Only one entry is defined today, and its function is maximize, applied to: Claude, VS Code, Notion, Cursor, Edge, Chrome, Brave, Firefox Dev Edition. That's a choice of this one entry, not a limit of the mechanism — add another entry with a different function for other apps and it works the same way. Also auto-applied on monitor plug/unplug (~2s after the screen settles) and on Hammerspoon reload.

Not Ctrl+Down/Ctrl+Up for this: macOS owns those (App Exposé / Mission Control) and swallows them before Hammerspoon sees the event — same reason the mode needs its own toggle key rather than reusing an arrow combo.
